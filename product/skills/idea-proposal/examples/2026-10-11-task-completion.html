01 Brief descriptionTicking tasks off

Tasks can be finished from two places, but not from the calendar

Today the operator can only complete a task from a dashboard insight or a reminder email. On the Tasks calendar there is no tick at all, and done tasks look the same as open ones. Completing a task gets a 500ms fade on the dashboard and a plain "Done" page from email, with nothing in between. The proposal adds a one-tap tick everywhere a task appears and keeps done tasks visible but dimmed. Each tick ends with one quiet line of group progress.

Who

A solo tour operator who plans traveller groups and their to-dos. They use it daily and finish tasks from the dashboard, email and calendar alike.

Today they

Tick from the dashboard or email, or leave calendar tasks alone. Done and open tasks look the same on the calendar, so the week never looks cleared.

Effort budget

Zero setup and one deliberate action per tick. The reward has to come on its own, with nothing to read and nothing to turn on.

Overlap: Completion already exists in the data and the API: is_completed plus PATCH /tasks/:id, the dashboard "Mark done" (insight-item.tsx:70) and the email Done button (action.controller.ts:73). Group history already logs task-done and shows "N open · M done". This proposal fills gaps. It is not a new system.

02 Feature detailTicking tasks off

Each MVP piece works with no setup and is harmless if ignored

Tick on the calendar

  • Trigger: tap the round tick on a chip, or "Done" in the popover.
  • Behaviour: optimistic update through useUpdateTask. The chip dims and its title is struck through. Tapping again reopens the task.
  • Empty state: no tasks means no ticks. Nothing new to explain.
  • Error state: the existing rollback undoes the tick, and the notice says "Couldn't save. Try again."
  • If ignored: the calendar behaves exactly as today.
  • Pending tasks: the tick is hidden until the server returns the task, same as editable.

The done moment

  • Trigger: any completion made in the app.
  • Behaviour: the tick draws in over about 300ms and the chip fades to dimmed over about 400ms. A notice fades in at the bottom with group progress and Undo, then fades out after about 5s.
  • Empty state: an ungrouped task shows "Done" with no count.
  • Error state: the same notice switches to the failure text.
  • If ignored: it leaves by itself, and nothing has to be dismissed.
  • Reduced motion: opacity fades only.

Group progress

  • Trigger: always on, and recomputed from the tasks list.
  • Behaviour: a thin fill under each group chip for done / total. On the last tick the chip glows once (about 4s, fading in from 0) and its label reads "Ready".
  • Empty state: a group with no tasks shows no fill. It never shows 0 of 0.
  • Error state: none of its own, because it only reads data that is already loaded.
  • If ignored: passive. It never asks for anything.

05 Potential tradeoffsTicking tasks off

The main risk is a tick that gets pressed by accident

TradeoffWhy it mattersSeverityMitigation
Accidental ticksChips are small and already respond to drag, resize and open-popover. A tick inside the chip competes with those, especially on mobile. A wrong tick also cancels the task's email reminder.HighShow the tick only on hover or focus on desktop, and only in the popover on touch. Always offer Undo. The undo reopens the task, and the existing reminder logic reschedules it.
Calendar package changeCalendarEvent has no way to style one event as done. A generic dimmed flag must be added to @alexgrossi/calendar, which has its own checks in CI.MediumKeep it generic (dimmed?: boolean), with no "task" concept in the package.
Cluttered calendarKeeping done tasks visible means busy days stay crowded with grey chips.MediumDim strongly (about 40% opacity). Hide done tasks in past weeks later if it bothers you.
The reward wears offThe same animation on the hundredth tick is noise. Reward design without variety fades within weeks (common product experience, not measured here).MediumKeep the per-tick moment small and save the visible moment for "group ready", which is rare.
New migrationAdding completed_at touches the shared tasks table and its history trigger. Old done tasks get no timestamp.LowBackfill from group_events.at where it exists and leave the rest null.
Opportunity costAn estimated 1.5 to 2.5 days (basis: three UI touch points, one ui component, one small migration) not spent elsewhere, e.g. the dashboard's AI briefing, which is still a local mock.LowShip the calendar tick first. It is half a day on its own and is the part that fills a real gap.
Strongest case against: You are the only user and already know how much you got done. A "reward" layer on a solo work tool can feel like being patted on the head by your own software. The functional gap (no tick on the calendar) is worth half a day. Everything beyond it is polish whose value only you can judge, and only after using it.

08 ConclusionTicking tasks off

Ship the calendar tick, then one calm "done" moment with group progress

The missing tick on the calendar is a real gap and costs about half a day. The reward is worth a small, quiet layer that saves its one visible moment for "group ready", not a game system.

Cut

  • Points and badges. They are a new concept to learn and clash with the notebook feel.
  • Sound (ruled out by you).
  • Streaks for now. They punish days off and the off-season for a solo operator.

Open questions

  • On a touch screen, should the tick appear on the chip at all, or only in the popover?
  • Should done tasks in past weeks fade further or hide?
  • Should the email Done page show progress in this round or later?

Next step
