Feature proposal · Hamstertours

Notes tab

A sidebar tab of short, categorised notes. Links open in one click and text snippets copy in one click, so routine bookings like hotels stop depending on bookmarks and memory.

Date2026-10-11
End userSolo tour operator, extremely low effort
Scale1 user, tens to low hundreds of notes (est.)
Verdict Build it, kept small It's cheap: one table, one route, and one feature folder, all following existing patterns. Writing a note is extra work up front, but it pays off from the second time the note is used.
01 Brief descriptionNotes tab

The booking routine lives in bookmarks and the operator's head

The operator repeats the same operations every week: booking hotels, writing to suppliers, finding the same login pages. The links are in browser bookmarks, and the rest (standard request text, which site is for which city, who to call) lives in their head. Nothing in the app holds this. The proposal adds a Notes tab to the sidebar: notes with a free-form category, a copy button, and clickable links.

Who

A solo tour operator planning traveller groups. Uses the app daily and won't read instructions or configure anything.

Today they

Use browser bookmarks plus memory. Standard texts are retyped or dug out of old emails.

Effort budget

Zero setup, one deliberate action. A note must be usable with just a title or body; the category is optional.

Overlap: Browser bookmarks already do the "open a link" half, and groups already have a free-text notes field (server/supabase/migrations/20261011000000_create_groups.sql). Group notes belong to one departure, though, so they can't hold reusable routines. The UI library also has an unused CommandPalette, and the login page already promises "⌘K anywhere".

02 Feature detailNotes tab

Each MVP piece works with no setup and is harmless if ignored

Notes tab with categories

  • Trigger: Clicking "Notes" in the sidebar.
  • Behaviour: Notes are grouped by category, most recently edited first. "New note" adds an empty card in edit mode, and it autosaves.
  • Empty state: One line, "Save a link or text you reuse, like your hotel booking site.", with the New note button.
  • Error state: A failed save keeps the text in the card and shows an inline retry. Nothing is lost.
  • If ignored: Nothing happens; the tab just sits in the sidebar.

Free-form category

  • Trigger: The category field on a note.
  • Behaviour: Suggests existing categories. A new name is created on save. Renaming a category means editing the notes in it (no category screen).
  • Empty state: No category means the note shows under "General".
  • Error state: Same as the note save.
  • If ignored: Everything sits under "General", which still works for a dozen notes.

One-click copy and open

  • Trigger: The copy button, or a link in the note body.
  • Behaviour: Copy puts the full body on the clipboard, and the button fades to a tick. Links open in a new tab.
  • Empty state: No copy button on an empty note.
  • Error state: If clipboard access is denied, the body text is selected so ⌘C works.
  • If ignored: Notes are still readable as plain text.

server/supabase/migrations/20261018000000_create_notes.sqlNew

Same shape and RLS stance as groups. The category is a column, not a table.

-- Reusable snippets and links, e.g. "Hotels / Booking.com partner login".
create table public.notes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  title text check (char_length(title) <= 120),
  body text not null default '' check (char_length(body) <= 10000),
  -- Free-form. Null shows under "General".
  category text check (char_length(category) between 1 and 40),
  is_deleted boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
alter table public.notes enable row level security;

08 ConclusionNotes tab

Ship the categorised notes tab with copy and open; add ⌘K next

It's small and follows patterns already in the repo, and it covers the routine the interview described. The risk is that the tab stays empty, and making ⌘K reach notes is the cheapest fix for that.

Cut

  • Checklists/playbooks: a second concept, and more clicks than the profile allows
  • AI categories: free-form was chosen, and mislabels would erode trust
  • A category management screen

Open questions

  • Should notes be usable on the phone during the day, or is desktop enough?
  • Should deleting a note be undoable, or is a confirm enough?

Next step

Pick the three options, then build in this order: migration, server module, notes feature + route, sidebar item. One commit each.
